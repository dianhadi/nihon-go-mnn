# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Cursor, etc.) working in this repository. Human-facing overview lives in [README.md](README.md).

## Project in one paragraph

A [Remotion](https://www.remotion.dev/) project that turns each **会話 (kaiwa)** of *Minna no Nihongo Shokyu II* (lessons 26–50) into a 3–5 minute illustrated short story video for YouTube (1920×1080, 16:9). The original kaiwa is only the seed: it is expanded into a longer story. No dialogue text is shown on screen; dialogue is delivered by one voice track per lesson (made manually in ElevenLabs) and by separate `.srt` subtitle files. The videos tell a story; they do not lecture, quiz, or explain grammar.

## Core principles

1. **Data-driven.** One generic composition renders any lesson from its data file. Adding a lesson = adding data + audio, not writing new composition code. If a lesson seems to need custom code, prefer extending the generic system (a new scene type, prop, or action) over a one-off.
2. **Reusable characters.** The same cast appears across lessons 26–50, keeping their names and roles from the book. Each character is drawn once as a layered 2D anime sprite set and rendered by one generic component (pose, expression, facing, talking state). Never redraw a character inside a lesson.
3. **Original artwork only.** Every visual (character designs, backgrounds, props) is created from scratch for this project. Book photos are *reference for story context only*: never trace, copy, embed, or closely replicate book illustrations.
4. **One audio file per lesson, timed per line.** Each lesson has a single voice track, generated by the user in ElevenLabs (not via API). Per-line start/end times live in `timings.json`, produced by the align script. The composition and the `.srt` generator both read that file, so video and subtitles never drift. Never hand-enter frame counts.
5. **No on-screen dialogue text.** Do not render subtitles, speech bubbles with text, or captions in the video. (Non-dialogue visual text like a shop sign is fine.)

## Tech stack

- Node.js LTS, **pnpm** (do not use npm or yarn; do not commit other lockfiles)
- TypeScript (strict)
- Remotion (latest stable 4.x)
- Composition: 1920×1080, 30 fps
- Voice audio: made manually by the user in ElevenLabs. **No ElevenLabs API calls in this repo.**
- Alignment: local whisper.cpp 1.7.6 via `@remotion/install-whisper-cpp` (no API key). Building it needs `git`, `make`, and `cmake` (`brew install cmake`); the model (`large-v3-turbo` by default) downloads into `.cache/` on first run.

## Content model

### `content/characters.yaml`
Each character has a stable `id` (kebab-case, e.g. `miller`, `sato`, `yamada-ichiro`) used everywhere: in story lines, component names, and voice mapping. Include display names (ja/en) and an optional `voice` (the ElevenLabs voice name the user picked, for reference). Voices are chosen by the user as lessons are produced; leave the field empty until then.

### `content/lessons/lesson-XX/story.yaml`
The source of truth for a lesson. Sketch:

```yaml
lesson: 26
title: { ja: "...", en: "..." }
scenes:
  - id: s01
    location: office          # folder in public/backgrounds/
    cast: [miller, sato]
    lines:
      - id: L26-001            # stable id; used by timings.json and i18n
        speaker: miller
        ja: "..."
        expression: happy      # optional; held until the speaker's next line that sets one
        pose: sitting          # optional; same holding rule
        action: walk-in        # optional; reserved, not rendered yet
      - id: L26-002
        pause: 1.0             # optional silence (seconds) after the line
        ...
```

Rules:
- **Line ids are stable and never reused.** Timings and translations are keyed by them. When inserting a line between `L26-004` and `L26-005`, use a new unused id (e.g. `L26-004a`); do not renumber.
- Japanese text in `ja` is the expanded story script and is what the voice is generated from.
- Translations live in `i18n/<lang>.yaml` as `line-id: text`, not inside `story.yaml`.
- Validate every content file against the Zod schemas in `src/schema/` (`pnpm validate`).

### `timings.json`
Generated by `pnpm align`. Shape: `{ audio: "audio/lesson-26.mp3", audioHash, linesHash, durationSec, lines: [{ id, startSec, endSec, confidence }] }`. Times are relative to the start of the audio file. Committed to git (small, and lets the project render once the audio file is present). Small manual corrections are allowed; `linesHash` detects them, and `pnpm align` refuses to overwrite a hand-edited file unless `--force` is passed. `audioHash` lets `pnpm validate` detect that the audio changed since alignment.

### Source material and the expanded story
- `source/` holds the user's photos and the original kaiwa. It is gitignored and must stay that way. Never move its contents into `content/`, `public/`, or `src/`.
- The story in `story.yaml` should be an *expansion*: new scenes, situations, and dialogue built around the lesson's theme and grammar so the result is an original short story of 3–5 minutes, not a verbatim copy of the kaiwa padded out.
- Keep language at the lesson's level: use grammar and vocabulary from that lesson and earlier lessons only.

## Voice audio (ElevenLabs, manual)

The user generates the audio in ElevenLabs by hand. This repo never calls the ElevenLabs API. The repo's job is to hand the user a ready-to-paste script and then recover per-line timing from the finished audio.

1. **Export**: `pnpm export-voice <lesson>` (or `--plain` for lines without speaker prefixes) writes `out/<lesson>/elevenlabs.txt`: the story's lines in order, one per paragraph, prefixed with the speaker name, plus a header listing each speaking character and their `voice` if set. Line ids are not included in the text (they would be spoken).
2. **Generate**: the user creates the full lesson track in ElevenLabs and saves it as `public/audio/<lesson>.mp3`. Leaving a short pause between lines improves alignment.
3. **Align**: `pnpm align <lesson>` transcribes the audio locally with whisper.cpp (word-level timestamps), matches the transcript to the story lines in order (fuzzy, character-level on normalized text), and writes `timings.json`. It reports lines it matched with low confidence so the user can check them in Studio.

If the user edits a line in `story.yaml`, they regenerate the audio (whole track or the affected part, spliced in ElevenLabs) and re-run `pnpm align`.

## Rendering pipeline

1. **Source**: user adds photos + original kaiwa to `source/lesson-XX/`.
2. **Story**: write `story.yaml` (expanded Japanese script, scenes, directions).
3. **Translations**: add `i18n/<lang>.yaml` for every subtitle language.
4. **Voice**: `pnpm export-voice lesson-XX` → user generates audio in ElevenLabs → saves `public/audio/lesson-XX.mp3`.
5. **Align**: `pnpm align lesson-XX` → `timings.json`.
6. **Validate**: `pnpm validate` checks schemas, that every line has a translation and a timing entry, and that timings match the story and the current audio file.
7. **Subtitles**: `pnpm srt lesson-XX` writes one `subtitles/<lang>.srt` per language from `timings.json`.
8. **Preview & render**: `pnpm dev`, then `pnpm render lesson-XX` → `out/lesson-XX.mp4`.

Composition duration is set in `calculateMetadata` from `timings.json` (plus intro/outro padding). `src/engine/timeline.ts` is the single timing module, used by both the composition and the SRT script. Before a lesson has `timings.json`, the timeline estimates line lengths from text length so the story can be previewed with placeholders.

## Remotion conventions

- All animation is driven by `useCurrentFrame()` with `interpolate()` / `spring()`. No CSS transitions/animations, no `setTimeout`, no `Date.now()`.
- Use `random(seed)` from Remotion for any randomness, never `Math.random()`.
- Use `<Sequence>` / `<Series>` for timing; use `staticFile()` for anything in `public/`.
- One `<Audio>` element per lesson playing the full track. Scene and line `<Sequence>`s are positioned from `timings.json`; a character's `talking` state is true while its line is active.
- Components must be pure functions of props + frame so renders are deterministic.
- Compositions are registered dynamically in `Root.tsx` from the lessons present in `content/`; do not hand-add a composition per lesson.
- The bundle reads content through `require.context` in `src/engine/bundle-content.ts` (YAML is loaded as raw text via the webpack rule in `remotion.config.ts`). Node scripts read the same files through `scripts/lib/content.ts`. Both validate with the schemas in `src/schema/content.ts`.

## Art: layered 2D anime

Characters and backgrounds are **layered 2D anime-style illustrations** (PNG with transparency), animated in Remotion by swapping and transforming layers. There is no mesh deformation (no Live2D-style warping): motion comes from layer swaps (eyes, mouth, expressions), small transforms (breathing, head bob, sway), and camera moves.

The user supplies the artwork (drawn, commissioned, or AI-assisted). Agents do not generate final art; they build the renderer, rig, and placeholders. All designs are original: characters keep their book names and roles, but never trace or closely replicate the book's artwork.

### Character sprite set: `public/characters/<id>/`

```
public/characters/miller/
├── rig.json                 # Layer order, canvas size, anchors, available poses/expressions
├── body/<pose>.png          # standing, sitting, waving, ... (includes head shape + clothes)
├── hair-back.png            # optional, drawn behind body
├── hair-front.png           # optional, drawn over face
├── eyes/<expression>-open.png
├── eyes/<expression>-half.png
├── eyes/<expression>-closed.png
├── brows/<expression>.png
├── mouth/<expression>-closed.png
├── mouth/<expression>-half.png
├── mouth/<expression>-open.png
└── extras/<name>.png        # blush, sweat drop, tears, ...
```

Rules for the art files:
- Every layer of a character uses the **same canvas size and alignment**, so layers stack without offsets. Recommended canvas: 2048 px tall.
- Characters are drawn **facing right**; facing left is a horizontal mirror.
- Face layers (eyes, brows, mouth) are drawn for the default head position. If a pose moves the head, `rig.json` gives that pose's face offset.
- Minimum expression set per character: `neutral`, `happy`, `surprised`, `sad`, `troubled`. Missing expressions fall back to `neutral`.
- File names are kebab-case and must match `rig.json`; `pnpm validate` checks that every file referenced exists.

### Background set: `public/backgrounds/<location>/`
Layered for parallax: `far.png`, `mid.png`, `near.png` (only `far.png` required), plus `rig.json` for floor line and character placement slots. Canvas 3840×2160 so the camera can pan and zoom without losing quality.

### Rendering behavior
- One generic `<Character id pose expression facing talking />` component renders any character from its `rig.json`. No per-character components.
- **Lip-sync:** while a character's line is active, mouth shape (closed/half/open) is chosen from the audio amplitude at the current frame (`@remotion/media-utils`), not from a fixed loop.
- **Blink:** eyes go open → half → closed → half → open at intervals from `random(seed)`, seeded per character.
- **Idle:** subtle breathing (small vertical scale on body) and slight head bob while talking.
- **Placeholders:** if a sprite set or background is missing, render a placeholder (colored silhouette with the character id) so a lesson can be previewed and timed before art exists.
- Sprite and background PNGs are committed to git. If the repo grows too large, move `public/characters/` and `public/backgrounds/` to Git LFS.

## Conventions

- All documentation, code comments, identifiers, and commit messages are in **English**. Japanese appears only in content data (`ja` fields) and Japanese subtitles.
- File and folder names: kebab-case. React components: PascalCase.
- Lesson folders are fixed: `lesson-26` … `lesson-50`.
- Subtitle languages (ISO 639-1): `ja` (Japanese, from `story.yaml`), `en` (English), `id` (Indonesian), `bn` (Bengali), `my` (Burmese), `ne` (Nepali). The list lives in one config constant; adding a language = adding it there plus `i18n/<lang>.yaml`.
- Translate from the Japanese, using `en` as a reference for meaning. Keep translations natural and short enough to read as subtitles. `pnpm validate` reports any line missing a translation in any language.
- `.srt` files are UTF-8 so Bengali, Burmese (Unicode, not Zawgyi), and Nepali (Devanagari) display correctly.
- Do not commit: `source/`, `public/audio/`, `.cache/`, `out/`.
